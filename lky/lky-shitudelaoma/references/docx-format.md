# 公众号文章 docx 版式规范

由 `scripts/build_docx.py` 统一实现，不要手搓生成脚本。下表是脚本实际写入的参数，
改版式就改脚本与本文，两处保持一致。

两个系列共用这套版式，差别只在章节骨架与图片来源声明：文献精读有论文快照、用论文原图；
学生信有常见问题与代码附录、用 matplotlib 模拟图，不写 `snapshot`。

| 元素 | 参数 |
|---|---|
| 页面 | A4，默认页边距（上下左右 2.54cm） |
| 正文 Normal | 微软雅黑 12pt（网页 16px），黑色 `#000000`，行距 1.5，段后 8pt，段前 0 |
| 主标题 | 22pt 加粗，居中，黑色 |
| 副标题 | 14pt，居中，黑色 |
| 一级标题 | 17pt 加粗，黑色，段前 28pt / 段后 14pt |
| 二级标题 | 14pt 加粗，黑色，段前 20pt / 段后 10pt |
| 三级标题 | 12.5pt 加粗，黑色，段前 14pt / 段后 8pt |
| 小目录 | 正文规格的普通段落，段后 4pt，逐行写 `一、xxx` |
| 开篇（仅学生信，可选） | 小目录之后的钩子段落，正文规格，逐段一个 `para` 风格的段落；放在正文各章之前 |
| 论文快照（仅文献精读） | `字段名：` 加粗 + 值，顶格（无 `/ ` 前缀），12pt，段前段后 2pt |
| 图片 | 居中，宽 5.2 英寸（约 13.2cm） |
| 图注 | 居中，**10.5pt（网页 14px）**黑色 |
| 来源声明 | 居中，10.5pt（14px）黑色，紧跟第一张图注下方 |
| 图后空行 | 图注（及来源声明）之后插入一个空段落，与正文隔开 |
| 并列项 | 独立段落，`· **名称**：说明`，12pt |
| 常见问题（仅学生信） | 每问一段 `[问题] 标题`（`[问题]` 加粗），紧接一段 `[回答] 正文`，12pt 黑色 |
| 附录代码（仅学生信） | 等宽字体 Consolas 10.5pt 黑色，逐行成段，行距 1.15，不缩进不断行 |
| 参考文献 | **9pt（网页 12px）**黑色，逐条一段 |
| 版权声明 | 文末居中排列，12pt 黑色；与正文之间空 20pt，不写 `———` 分隔线 |

要点：

- 全篇纯黑，含标题：正文、图注、表注、各级标题都不用灰色或其他颜色，旧版 docx 的深蓝标题与灰色 9pt 声明行都已作废。
- 层级只靠字号与加粗区分，不靠颜色。
- **px 与 pt 换算**：Word 里 12pt = 网页 16px（正文），10.5pt = 网页 14px（图注），9pt = 网页 12px（参考文献）。脚本里已写死，不要再改。
- **副标题独立成行，不以 `——` 开头**；文末也不写 `———`，靠留白分段。成稿后按 `$lky-polish` 完成去 AI 味改写与段落逻辑核查。
- 标题字号按上表固定，不随文章长度变化。
- 图注必须能独立读懂，且不与正文重复长句；图注之后必须空一行再接正文。
- 文件名用全角冒号，不要用 `/`、`:` 等字符（历史脚本在 Windows 上吃过静默失败的亏）。
- 生成后把 docx 转 PDF 翻一遍：确认中文字体没有方框、图片没有超出页边、快照没有断行错位。

```bash
PY=/Users/oldma/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3
$PY ~/.codex/skills/lky-shitudelaoma/scripts/preview_docx.py <文章.docx> --out /tmp/docx-preview
```

**必须用这个脚本转，不要直接调 soffice**：本机 LibreOffice 自带的 fontconfig 看不到系统中文字体，
裸转换会把中文渲染成空白，看着像排版坏了，其实是渲染环境缺配置。脚本会写一份指向
`/System/Library/Fonts` 的 fontconfig 配置再转换，并顺便把每页渲染成 PNG 供逐页核对。

## 内容 JSON 结构

`build_docx.py` 接受这样一个 JSON：

```json
{
  "title": "老马文献精读（21）：论文标题直译",
  "subtitle": "一句有信息量的副标题，不加破折号前缀",
  "fig_dir": "/绝对路径/第21期 主题",
  "output": "/绝对路径/第21期 主题/老马文献精读（21）：主题.docx",
  "snapshot": [
    ["期刊", "Nature. 2026;640:1-10"],
    ["文章摘要", "原文 Abstract 的完整中文翻译"]
  ],
  "intro": ["开篇钩子段落（仅学生信使用，可省略）"],
  "toc": ["一、这篇文章要解决什么问题", "二、研究设计与方法论"],
  "sections": [
    {
      "heading": "一、这篇文章要解决什么问题",
      "level": 1,
      "blocks": [
        {"type": "para", "text": "研究思路第一段：领域共识与留下的空白。"},
        {"type": "para", "text": "研究思路第二段：核心假设与论证链怎么走通。"}
      ]
    },
    {
      "heading": "二、研究设计与方法论",
      "level": 1,
      "blocks": [
        {"type": "sub", "text": "设计层：技术路线"},
        {"type": "point", "items": [["原理", "为什么这个方法能得到结论"]]},
        {"type": "image", "file": "km_fig1.png", "caption": "图1 总体流程。", "disclaimer": true}
      ]
    }
  ],
  "references": ["[1] Author A, et al. Title. Journal. 2024;10:1-9.（JCR Q1，2024 IF 20.0，中科院1区）"],
  "footnote": [
    "本文版权归论文原作者及期刊所有，本解读仅供学术交流，不构成医学建议。",
    "原文：作者. 标题. 期刊. 年份."
  ]
}
```

block 只有六种类型，够用且不容易写错：`para`（正文段落）、`sub`（二/三级标题，`level` 默认 2）、
`point`（`· **名称**：说明` 并列项）、`image`（图片加图注，首张图带 `disclaimer: true`）、
`qa`（常见问题，`items` 是 `[问题, 回答]` 数组的数组）、`code`（附录代码，`text` 按换行拆段，`lang` 可省）。

图片来源声明默认写「（声明：本文图片均来源于论文原文，仅供学术交流，不构成商业用途）」；
JSON 顶层写 `"series": "学生信"` 会自动换成「（声明：本文图片均为模拟生成，不代表真实数据）」；
也可以用 `disclaimer_text` 显式覆盖，单张图还能用 `image` 块里的 `disclaimer_text` 单独覆盖。

注意：`snapshot` 必须给全 8 个字段（含 `文章摘要`，不含 `研究背景` / `数据来源` / `研究方法`；
分区与影响因子只写数值，不加括号注释）；`文章摘要`必须按
[abstract-translation.md](abstract-translation.md) 完整翻译原文 Abstract，不做二次归纳；
第一章只放 1-2 个 `para`，`sub` / `point` / `image` 从第二章开始用。
学生信不写 `snapshot`，章节顺序按 [xueshengxin.md](xueshengxin.md)。
