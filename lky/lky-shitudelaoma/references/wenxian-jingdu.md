# 老马文献精读 · 规范

成品：`老马文献精读（N）：主题.docx`，配图 `km_fig{N}.png` 与 docx 同目录。
一期解读一篇论文，重点是**研究思路、方法论、结果解读，以及与以往研究的不同**。

## 章节结构

```
主标题：老马文献精读（N）：论文标题直译
副标题：一句有信息量的提炼，居中另起一行
论文快照（8 个必备字段）
小目录
一、这篇文章要解决什么问题   <- 只写 1-2 段
二、研究设计与方法论          <- 全文最重的一章
三、结果解读
四、与以往研究的不同
五、不足与局限
---
版权声明 + 原文出处（靠留白分段，不写破折号分隔线）
```

不再设「老马说说」章节。点评属性融进「与以往研究的不同」和「不足与局限」的论述里，不要单开一章。

## 8 个必备字段

论文快照按 `字段名：值` 逐行排列，**顶格书写、不加 `/ ` 之类前缀**，标签加粗：

| # | 字段 | 说明 |
|---|---|---|
| 1 | 标题 | 论文英文原题 |
| 2 | 期刊 | 全名 + 年卷期页码或文章号 |
| 3 | DOI | 原文 DOI |
| 4 | 分区 | 只给数值，例：`中科院1区 / JCR Q1`。不加括号注释，不写学科名与 Top 标记 |
| 5 | 影响因子 | 只给数值，例：`48.5`。不写发布年份，不加括号注释 |
| 6 | 主要作者 | **只写第一作者与通讯作者**，英文原名不译，各自用括号标注所属单位；通讯作者标明「通讯」。例：`Zhang San（XX大学）；Li Si（通讯，YY大学附属医院）` |
| 7 | 文章摘要 | 原文 Abstract 的完整中文翻译，按 [abstract-translation.md](abstract-translation.md) 执行；保留研究对象、方法、结果、限定语与证据强度，不改写不增删 |
| 8 | 创新点与不足 | 亮点与局限各点到位 |

**已取消的字段**：`研究背景`、`数据来源`、`研究方法` 都不再进快照。研究背景归第一章；
研究方法、样本量、队列与数据集细节归第二章研究设计。`研究主要发现` 换成 `文章摘要`，
是把原文摘要完整译成中文，不是自己重新归纳一遍发现。翻译时按
[abstract-translation.md](abstract-translation.md) 拆解长句、统一术语并逐项校回原文。

## 各章写法

### 一、这篇文章要解决什么问题

**篇幅严格控制在 1-2 段**（第二章和第三章才是重点，这里不要铺开写背景综述）。
只讲研究思路：领域里已有的共识是什么、留下的空白或矛盾在哪里、作者的核心假设是什么、
打算怎么把这条论证链走通，为第二章做引子。方法细节、样本量、数据集、结果清单都不写在这一章。

### 二、研究设计与方法论（重点章节）

这一章通常占全文三分之一以上，分两层写：

**设计层**：技术路线总览。每个模块承担什么角色、为什么这样组合、队列与样本量怎么来的、
对照怎么设、统计策略是什么、什么样的结果才算支持假设。

**方法层**：逐个拆解关键方法。每一项写清楚四件事 ——
原理（这个方法凭什么能得到结论）、关键参数与阈值、在这里为什么选它（而不是其他候选）、
代价与已知缺陷。

写作要求：读者读完这一章，应当能自己判断「这套方法能不能支撑第三章的结论」。
禁止只罗列软件名和流程步骤。方法名首次出现给全称与简称，后文统一用简称。

### 三、结果解读

用论文原图逐图解读，顺序与原文一致。每张图讲三件事：
图里展示的是什么、数值本身说明什么、它支持了第二章哪一步推理。
严格区分「作者证明了」和「作者提示了」；相关性结果不写成因果。
图注要能独立读懂（读者只看图不看正文也知道这张图在说什么）。

### 四、与以往研究的不同

先用 `lky-search` 检索主题相关的既往文献，挑 3–8 篇代表作，逐项对比：
别人做到哪一步、这篇往前推进了什么、结论是否一致、如果矛盾可能是什么原因。

写成有主语有对象的对比（「相比 X 等人的队列研究，本文……」），不要写成「本文首次……」的自我宣称。
被对比的文献要补进文末参考文献。

检索示例（联网命令用 `~/.codex/bin/vpnctl p` 包裹）：

```bash
python3 /Users/oldma/.codex/skills/lky-search/scripts/lky_search.py search \
  --query "topic keywords" --year-from 2021 --limit 20 --sort cited
python3 /Users/oldma/.codex/skills/lky-search/scripts/lky_search.py related --doi 10.xxxx/xxxxx
```

### 五、不足与局限

逐条写，避免空泛。优先写设计层面的局限（队列代表性、对照、验证层级、外推性、样本量），
其次写方法层面的（参数稳健性、算法假设、跨物种或跨平台外推）。
论文自己承认的局限与作者没提但客观存在的局限要分开呈现。
**写完局限就收尾，不要在章末追加概括研究价值的收尾段**（例如「这项研究留下的主要资产是……」）。

## 配图

- 用论文原图，不重绘不模拟。命名 `km_fig{N}.png`，按 `km_fig1` 起的顺序与正文一致。
- 第一张图图注下方加一行：
  `（声明：本文图片均来源于论文原文，仅供学术交流，不构成商业用途）`
- 需要额外示意图辅助说明时，先征得用户同意再画。
- 提取流程见 `scripts/extract_pdf_figures.py`：先用 `--list` 看每页的嵌入图与页面尺寸，
  能直抽的嵌入图直接抽，主图这类矢量渲染的用整页渲染再按坐标裁剪（不要整页截图了事）。
- 插入 docx 前把图片压到 1200px 宽（脚本 `--compress`）。

## 参考文献格式

```
[N] Author A, Author B, et al. Title. Journal. Year;Vol(Issue):Pages.（JCR Qx，YYYY IF x.x，中科院x区）
```

纯文本，不加超链接、不加 DOI。原始方法论文优先于综述。

排版：9pt（网页 12px）黑色，逐条一段；文末最后一条之后不再接其他段落。

## 文风

- 学术化评价，不用口语（「比较扎实」写成「较为系统」，「落空了」写成「未能回答」）。
- **中文表达优先，不要机翻味**：按中文语序重新组织句子，不逐词照搬英文原句。
  英文的长定语从句拆成短句；一句话里不连用多个「的」；被动式（「被证实」「被发现」）改成中文的主动说法或直接陈述。
- **摘要翻译必须逐句校回原文**：执行 [abstract-translation.md](abstract-translation.md)，
  完整保留对象、方法、结果、限定语和证据强度；数字、单位、基因名、缩写按原文不动。
- 标题与其余正文的翻译以读得通为准，术语按领域惯例翻译。通读一遍，需要回读才懂或者读着拗口的地方，就是还没润色到位。
- 用引导性提问替代平铺直叙（「这说明什么？」而不是「这表明……」）。
- 副标题要有信息量：只看目录的读者也能拿到核心结论。
- 不为论文背书。作者没做的验证就写没做，不要替作者圆场。
- 标题层级下的正文一律黑色统一字号，长段落拆短，每段只讲一件事。

## 生成 docx

把内容写成 JSON，交给 `scripts/build_docx.py`，正文结构与版式规范见
[docx-format.md](docx-format.md)。数一下原图：正文每张图都要有对应的 `km_fig{N}.png`，
缺图会在 builds 阶段直接报错。

```bash
PY=/Users/oldma/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3
$PY ~/.codex/skills/lky-shitudelaoma/scripts/build_docx.py 第21期内容.json
$PY ~/.codex/skills/lky-shitudelaoma/scripts/check_article.py "第21期 主题" --series 文献精读
$PY ~/.codex/skills/lky-shitudelaoma/scripts/preview_docx.py "老马文献精读（21）：主题.docx" --out /tmp/docx-preview
```

章节标题照抄结构里的五章名，自检脚本按这几个名字核对；不要再用「六、老马说说」。
